Is the analysis trustworthy? Monte Carlo over 300 seeds

Runs this scenario 300 times with different seeds. On a healthy release, the rollback rate is the false-positive rate, which should stay at or below α. With a regression, it shows detection power.

How it works

Each minute, traffic splits between stable and canary by the current step weight. Errors are drawn from binomial distributions and latencies from log-normal ones, using a seeded PRNG so every run can be reproduced. Every few minutes the analysis compares everything collected in the current step:

  • Errors: a one-sided Fisher's exact test. At 1% weight the canary sees a few hundred requests and single-digit error counts. A normal-approximation z-test fired at 1.2% against a nominal 1% in this simulator's own Monte Carlo runs, so the exact test replaced it.
  • Latency: a one-sided Mann-Whitney U test, which makes no normality assumption about tail-heavy latency.
  • Peeking: repeated looks inflate false positives, so α is split evenly across every look and both metrics (Bonferroni).
  • Practical significance: the step fails only if the result is significant and the effect is large enough to matter (+0.2 percentage points of errors, or more than 10% slower at p50).

Exposure compares the canary with an all-at-once deploy over the same wall-clock time. Everything runs locally in your browser.
